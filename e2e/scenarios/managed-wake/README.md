# Controlled managed Issue wake

Run independently with `npm run e2e -- --group managed-wake` after the framework
has prepared compatible CLI and Core sources. Missing or incompatible producers
are reported as unavailable prerequisites. Linux and the CLI's Go toolchain are
required. Source acquisition, packaging and compatibility remain framework-owned.

The package-local Go driver runs CLI managed activation from an inactive matched
adoption. Producer transport helpers supply synthetic provider and host responses.
The driver records configuration readback, destination, adopted member and two
synthetic Runner slots, and checks preparation, suppression and resume ordering.
Legacy-route conflict and missing configuration readback must stop activation.
No systemd operation, registration, login, PAT or Actions secret is created.

That configuration feeds Core's maintained payload producer and NotificationRelay.
The hosted ZIP boundary, origin run, artifact metadata, destination run, jobs and
clock are controlled provider data. Mutation replies are separate from reads.
Each invocation recreates the relay and journal object over the same private
journal directory. Unknown dispatch identity remains pending; exact recorded
identity may recover after readback becomes available. Newer attempts never
replace the original. Case names and mandatory selection live in cases.mjs.

The actual dispatch envelope enters Core's forwarded wake validation and current
state Shape selection. The existing native evidence helpers correlate independent
Issue, origin, artifact, exact destination run and Runner reads with that selection.
Missing evidence and altered identities must prevent a passing correlation.
Selection is explicitly separate from stage admission and completed execution.

All results are synthetic. They certify neither hosted artifact transport nor a
live installation, Runner execution or release readiness. Disposable copied source,
payloads, synthetic data and journals are removed after owned processes terminate.
Unknown process termination retains recovery state through the framework owner.
